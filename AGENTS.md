# AGENTS.md

Guidance for coding agents (Codex, Claude Code, Kimi Code and others) working in this repository.

## Repository layout

This repository **is** the publishable npm package `@restless-dreams/orbit` (the library is called Orbit and its command `orbit`; "orbit-md" names only its markdown format) — a single package at the root, no monorepo or workspaces. GitHub: restless-dreams/orbit.

- Public entry: `@restless-dreams/orbit` (framework-agnostic — parsers, serializers, renderer, web component). Optional subpaths: `@restless-dreams/orbit/react` (React wrapper) and `@restless-dreams/orbit/marked` (marked integration). `react`, `react-dom`, and `marked` are optional peer dependencies.
- Source lives in `src/` (`src/core`, `src/react`, `src/marked`); unit tests in `tests/`, browser tests in `e2e/`; the `orbit` CLI in `bin/`; the build, benchmark and docs scripts in `scripts/`.
- The first release is 0.1.0, and versions stay 0.x while Orbit still changes a lot. Releases are made by hand, never by a workflow, and their notes are posts on the website, not a changelog file (see `RELEASE.md`). There is no earlier format or API to stay compatible with.
- The website, https://orbit.hyuchia.com, lives in its own repository and runs a build of this one. Its docs (https://orbit.hyuchia.com/docs) are this repository's `README.md` and `docs/`.

## Commands

Run from the repo root.

```bash
bun install
bun run verify                           # lint + typecheck + test + build (run before PRs)

bun test                                 # unit tests (tests/ only; bunfig.toml sets the root)
bun run lint
bun run typecheck
bun run build                            # ESM + .d.ts into dist/
bun run test:browser                     # Playwright in the official container: e2e/ interaction + screenshots
bun run bench                            # animation frame rates on a large made-up map (scripts/large-map.js) against 60 fps; -- --profile=phone, -- --map=huge, -- --map=<file>
bun run docs:api                         # regenerate docs/api (TypeDoc, markdown)
```

Run a single test (the `bunfig.toml` `[test]` preload registers happy-dom, so no `cd` is needed; otherwise `document is not defined`):

```bash
bun test tests/renderer.test.ts
bun test tests/renderer.test.ts -t "framing"
```

## Library architecture

The pipeline is **parse → layout → scene → display → paint**, kept as separate modules so each can be tested in isolation:

1. `core/parser-markdown.ts` / `core/parser-yaml.ts` / `core/dispatch.ts` — `parseOrbit` is the public dispatcher; it routes to `parseOrbitMarkdown` (real markdown: headers + bullet lists nest the tree, HTML comment `<!-- orbit ... -->` blocks carry typed attrs, blockquotes are explicit notes that never re-tokenize as structure) or `parseOrbitYAML` (structured authoring; scalar `children` entries are text-only leaf shorthand) based on the first content line. Both flavors return an `OrbitDocument` with `root`, `options`, and `warnings`. `core/yaml-mini.ts` is the in-house tiny YAML subset (parser + emitter, no runtime deps) — the emitter only uses `|` block scalars it can re-parse exactly (see `blockScalarSafe`), JSON-quoting everything else. `core/media.ts` holds video provider detection / id extraction / embed-URL conversion shared by parser, renderer, detail sheet and media viewer — anything that iframes a video URL must go through `toVideoEmbedUrl` (watch pages refuse framing).
2. `core/layout.ts` — pure geometry, internal (not exported from the package). `calculateFocusLayout` (sun + planets on rings) and `calculateAllLayout` (recursive subtree placement with `MAX_FAN_DEGREES = 270` for non-root branches). Both place the focal node (sun or root) at exactly `(cx, cy)`. Both honor `LayoutConfig.maxDepth`. Focus rings are planned for the planets' bodies; `makeRoomForMoons` then moves a ring (and the rings beyond it) out only as far as the moons need: a moon keeps `MOON_CLEARANCE` from other planets and a moon's radius from their moons, and stays nearer its own planet than its neighbors on the ring. Where moons have room, the rings stay as planned. `moonPlacement` is where moons go, for the layout and the scene alike. The room moons need depends on their neighbors, so a drag along the orbit keeps the rings it began with until the drop (`SceneOptions.keptRings`). Colors are not the layout's job: see Color rules.
3. `core/engine/` — the scene engine, pure except for `views.ts`:
   - `scene.ts` turns a tree into a `Scene` for a view: nodes keyed by id with world positions (the focus node at the origin), rings with gaps around their bodies, links, and `frame`, the camera that fits it. `buildFocusScene` adds the planets' children as moons (`MOON_LIMIT`, placed by `moonPlacement`); `buildOverviewScene` wraps `calculateAllLayout`.
   - `camera.ts` — a camera is the world point at the viewport center plus a scale. `smoothZoomPath` is the van Wijk–Nuij path flights follow; similarity transforms place one scene inside another.
   - `display.ts` — what is on screen this frame: `sceneDisplay` (a scene at rest, orbit turned by the spin angle) or `transitionDisplay` (the previous display morphing into the target scene placed by `placement`: shared nodes move, new ones grow out of their parent, leaving ones shrink into theirs or fade).
   - `spin.ts`, `glide.ts` — time-based physics: release velocity is the least-squares slope of the last 80 ms; coasting decays exponentially with the exact per-step solution, so frame rate never matters.
   - `animation-clock.ts` — one requestAnimationFrame loop per map; tasks advance with elapsed time, then the map paints once. It sleeps when nothing moves.
   - `views.ts` — keyed DOM views. `NodeView` is an SVG group drawn at unit radius and positioned with one `translate() scale()`; `NodeLabel` is HTML in screen space, drawn from a `LabelDrawing` each frame. `labelPlacement` / `insideLabelLayout` decide where a name goes: inside its node whenever it fits the circle (shrinking to 9 px and wrapping at `wordPieces`, then cut short with an ellipsis if at least 8 characters show), outside as a pill only for pictures, overview nodes whose whole name doesn't fit inside (they never cut it short) and a sun too small for its name; otherwise nowhere until you zoom in. Every line of a fitted name fits the circle where it's drawn, however many lines the fit tried. A name keeps clear of its node's "+N" (`COUNT_POSITION`, `measureCount`; `planLabels` passes its width when the map draws counts, which exports don't): its lines and icon rise until the last line's letters clear it, as far as the circle allows (`InsideLabelLayout.lift`), and a line still beside it ends short of it, so the name may come out smaller. A pill keeps 5 px from its node on every side (`pillDistance` in `labels.ts`): on a slant it sits farther out, where its nearest end clears the node too. Fitted names are written as their lines (`white-space: pre`); only pills wrap in CSS, at `<wbr>` hints. `export.ts` and `colors.ts` build the standalone SVG for `toSVGString()`.
4. `core/svg-renderer.ts` — `OrbitSVGRenderer` ties it together. It owns the options, focus path, view mode, the current `scene`, the `camera`, an optional `transition` and the spin physics. **Navigation never rebuilds the DOM**: `navigate()` builds the target scene, `placeTarget()` finds a node both views show (the target's focus on screen → zoom in; today's focus in the target → zoom out; any shared node; then ancestors) and the flight keeps it fixed; with nothing in common it flies through the common ancestor's scene (`nextScene`). When a flight lands, the world is re-rooted on the target (`camera = target.frame`, spin angle 0) and the picture doesn't change. Pan and zoom only move the camera. In focus mode, zooming past `ENTER_ZOOM` toward a planet or moon at least `ENTER_RADIUS` px on screen enters it (so crowded orbits can be zoomed into and read), zooming below `EXIT_ZOOM` goes up a level (to the overview from the root), and a partial zoom-out springs back. `paint()` syncs the keyed views once per frame. SVG ids are per instance (`this.ids`). Each instance is registered in a static `WeakMap`; consumers must call `OrbitSVGRenderer.unmount(host)` after detaching the host. The web component (`core/auto-render.ts`) does this in `disconnectedCallback`.
5. `core/input-controller.ts` recognizes gestures (Pointer Events, wheel, pinch, double tap) and leaves their meaning to the renderer (`dragGesture(point)` picks spin, pan or nothing). Never `preventDefault` pointerdown or taps stop generating `click` on touch — touch scrolling is managed with `touch-action` in the stylesheet; capture the pointer only once a drag engages; swallow the click that ends a drag or catches a spin.
6. `core/ui/` — the HTML around the map: `controls.ts` (breadcrumbs / back chip, view switch, list button, zoom buttons), `detail-sheet.ts` (native `<dialog>`), `outline.ts` (the map as a list, live region, tooltip), `actions.ts` (the focused node's buttons; where they go is in Centering and fitting), `note-markdown.ts` (notes rendered as DOM, never as raw HTML), `icons.ts`, `frames.ts` (pages framed with no referrer; YouTube's and Vimeo's players with the page's origin, which YouTube's needs). `media-viewer.ts` is the media viewer: a modal `<dialog>` over the whole window that "View image" and "Play video" open (unless `mediaViewer: false`), stepping through `galleryItems` (the map's pictures and videos in outline order); `media-zoom.ts` is its pure picture geometry (fit, clamp, zoom around a point), and `media-players.ts` plays files in `<video>` and drives YouTube's and Vimeo's players through the messages their own APIs send. On maps that aren't interactive the viewer takes no input; `openMedia` and the other media methods drive it.
7. Styles: `core/styles/orbit.scss` (nested BEM, compiled to a CSS string by `scripts/sass-plugin.ts`) plus the theme CSS generated in `core/themes.ts`; `core/styles.ts` adds both once per document or shadow root (`adoptedStyleSheets`, `<style>` fallback). Public `--orbit-*` custom properties resolve through private `--_orbit-*` ones, so page CSS beats a `theme` object, which beats the preset. Chromium makes an SVG element with focus listeners a tab stop of its own, so focus listeners live on the HTML root.
8. `core/extensions.ts` — node types, actions and status words. A map's options (`nodeTypes`, `actions`, `statuses`) come before the registered ones (`registerNodeType`, `registerAction`, `registerStatus`); the renderer, detail sheet, outline and exporter read icons, colors, type tokens and status looks through one `MapExtensions`, never from the node alone. A type's `render` draws into `.orbit__contents`, an HTML layer moved with the nodes each frame. Named themes (`registerTheme`) live in `core/themes.ts` and expand to `{ preset, tokens }` objects (`expandTheme`).
9. `core/languages.ts` — the words Orbit shows and says, by language (`OrbitStrings`: English and Spanish built in, `registerLanguage` for more). A map's `OrbitWords` come from the `language` option or the closest `lang` around its element (`languageOf`, through shadow roots); every UI module takes them from the renderer, which calls their `relabel` when the language changes (`syncLanguage`). Never write English into the UI directly: add a key to `OrbitStrings` with its Spanish, and `tests/languages.test.ts` checks both tables have every key and the same placeholders.
10. `core/editing.ts` — tree edits behind the renderer's `addNode`, `updateNode`, `removeNode` and `moveNode`, and the map tools: `addToTree`, `updateInTree`, `moveInTree` and `removeFromTree` change a tree, and the renderer adds what a view needs (renamed views, `changedIds`, `afterEdit`). Ids follow the parsers' rules (`nodeSlug` + `-2`, `-3`… in document order), and new text gives a node a new id unless a link points at it, so saved maps need no id attributes for nodes made or renamed on the map. Edits go through `showTree` (a morph); a node whose id changed is renamed in the morph's starting display (`renamedIds`) so it moves instead of leaving and arriving. `render()` of a different object holding the same map (`isSameMap`) adopts it without redrawing, so an editor saving and re-rendering never cuts an edit's animation short. Long presses (`InputController.onLongPress`, touch and pen only), `contextmenu` and the context menu key all go through `openNodeContext`, which reports each press once and only takes it (no click, no browser menu) when someone listens.
11. Typing on the map — `editable` maps lay out one more planet slot in focus scenes (`SceneOptions.addSlot`, `Scene.addSlot`, carried through displays and transitions as `Display.addSlot`) and draw it as the + (`AddSlotView`). `ui/inline-editor.ts` is the field: a textarea laid over the node or the + each frame (`placeEditor`), with a 16 px font scaled to the label's size so phones don't zoom. Over a node with a "+N" it rises as it grows, as names do (`EditorPlacement.lowest`). An `EditSession` says what it types into: a node, or a new idea at an index (the + moves there). Enter on a new idea moves the session to the next index before inserting, so the rebuilt scene already has the + after the new node, and `arrival` starts the new node where it was typed. The edited node's label is hidden and its view gets `orbit-node--editing`.
12. `core/map-tools/` — tools a language model calls to read and change a map (`createMapTools`). `definitions.ts` names and describes each tool and converts the definitions to each provider's shape; a tool's input is written once as fields (`input.ts`), which give both the JSON Schema the model reads and the checks every call goes through. Keep the schemas plain (no `$ref`, unions, `additionalProperties` or `default`) so every provider takes them: new branches come as orbit-md outlines, read by the markdown parser, instead of nested objects. `tools.ts` carries out calls on a map on screen, through the renderer's edit methods so changes animate and fire `edit`, or on a document, through `core/editing.ts`. A call a model gets wrong throws `CallError` or `InputError` inside and comes back as `{ ok: false, text }` with nothing changed; results name nodes as `"Title" #id`. `reading.ts` writes the outlines, details and search results models read. When changing a description or a result, try it with real models: `tests/map-tools.test.ts` checks the words, not how models take them.

### Centering and fitting

The focus node sits at the world origin and `fitAround` keeps it at the viewport center: scale by the worst-case extent from the focus node, never by bounding-box centering — for asymmetric child counts (1, 3, 5, 7) the bounding box's center is below the sun, which would visibly push the sun off center. In focus mode `clampCamera` keeps the sun centered at the fitted zoom and allows panning only as far as the zoom goes past it. Tests in `renderer.test.ts > framing` lock this in.

The `insets` option (the parts of the map a page covers with its own controls) shrinks what `fitAround` fits into and moves the fitted camera the other way, so the focus node sits in the middle of what's left; `clampCamera` clamps around that frame, so the offset holds. The camera's projection itself stays centered on the viewport.

The focused node's buttons (`actionsPlace` in `svg-renderer.ts`) never cover a planet at any turn of the orbit: they go under the sun where the inner ring leaves room for the whole row (its farthest corner, not just straight down), else on the sun's lower rim under its name, else under the orbit, centered under the sun. Under the orbit they keep clear of the zoom buttons (`Controls.zoomBox`, which mirrors their stylesheet), wrapping onto more lines (`actionRows`) if they must. Where the fitted view leaves no room for them there, `focusScene` refits only the frame (`fitScene` with `below`): the orbit is fitted into what's left above them, which costs nothing on a phone held upright (it has height to spare) and the buttons' height where the map's height is all used. Zoomed in, the orbit grows over that place and the buttons hide until the view is fitted again. A change to `insets`, `showActionButtons`, `interactive` or `showControls` refits the view. `tests/renderer-buttons.test.ts` and `e2e/buttons.spec.ts` (the large map on a phone, at every turn) lock this in.

### Color rules

`assignNodeColors` (in `engine/scene.ts`) gives every node one color in every view: the root is `palette[0]`, each top-level branch takes the next entry, and descendants use their branch's color mixed toward the theme's `shade-light` or `shade-dark` token by sibling position (`color-mix(in oklab, …)`). So a focused planet keeps its color when it becomes the sun. Per-node `color` attrs (set via `<!-- orbit color: ... -->` in markdown or as a `color:` key in YAML) always win. Without a custom palette the colors are `var(--_orbit-color-*)` theme tokens.

### Every frame

`paint()` runs on every frame while anything moves (flights, spins, the drift, pans), on maps with thousands of nodes, so keep it to arithmetic and writes that change something:

- Text is measured once: label fits (`textMetrics` in `views.ts`) and pill widths (`measurePill` in `labels.ts`) are cached by text, and "+N" widths (`measureCount` in `views.ts`) by font and number of figures.
- Views keep the strings they last wrote (transforms, opacity, a link's geometry, a badge's count, the focused node's buttons' place) and touch the DOM only when they change. New text means layout and shaping, so never set `textContent` on every frame.
- Read computed styles before any write in a frame (`paintLabels` asks for every new node's text color first), never between writes.
- Label spots find nearby bodies and labels through `ScreenGrid`, not by checking all of them. `tests/labels.test.ts` compares `planLabels` with a plain check of every rule on hundreds of random maps, and checks every pill keeps its gap from its own node.
- Navigation only moves the outline's `aria-current` (`AccessibleOutline.setCurrent`). The list, thousands of entries on a big map, is rebuilt when the map, `maxDepth`, `interactive` or the extensions change.
- `getNodeColor` keeps the map's colors until the map or its options change, and reads theme tokens once per task. Parsing checks `#id` links against an index (`indexNodes`), never a tree search per link.
- In flights, the nodes that come or go with their siblings (growing out of their parent, shrinking into it, fading where they are) carry a `cluster` (`display.ts`). Nodes are drawn in groups of siblings (`Family` in `svg-renderer.ts`), and a group whose members share a cluster moves as one: one transform per frame instead of one per node. A flight's arrivals get a group of their own, groups stay as they are when a flight lands (so nothing is reparented then), a group whose members part ways splits, and hidden newcomers are created over a flight's first frames (`NEWCOMERS_PER_FRAME`).
- While only the camera moves (pans, pinches, zooms, glides), labels and "+N" counts ride along as one layer (`labelRide`) and are placed again when the camera rests, or once they'd be `RIDE_ALONG_ZOOM` bigger or smaller or `RIDE_ALONG_PAN` away.
- The drift rests while the camera moves and paints only once its turn moves the outermost body `DRIFT_STEP` px: a clock task returns `'hold'` to keep running without a paint.
- A spin turns the layers the planets and moons are in (`OrbitTurn` in `display.ts`, `paintTurn` in `svg-renderer.ts`): each body is drawn where it is in the unturned orbit, so a spin is one transform per frame instead of one per body. A body whose look shows which way is up (its shading, badges, picture or shadow) is turned back upright on its own. Specks, flat bodies under `SPECK_DEVICE_RADIUS` device pixels (`speckRadius` in `views.ts`), turn with the orbit, shading and all, and are lit from the top left again once it rests (`turnShading`: changing their gradient redraws every speck, so never on every frame). Specks are drawn with their circles' own coordinates and no transform, so Chromium paints thousands of them as one chunk instead of rebuilding its layers for each one every frame; their badges are left out and their rims scale with them. A node travelling on its own in a flight is drawn as a body (one write to move it), and at most `SPECK_SWITCHES_PER_FRAME` nodes become specks or stop being them in a frame. While only the camera or the turn changes, `paintNodes` updates only the bodies turned back upright (`stillNodes`).
- Don't give every node an outline kept the same width on screen (`vector-effect: non-scaling-stroke`): Chromium lays each one out again whenever anything above it moves, camera included. Badges and the rims of crowded orbits and specks scale with their nodes; the halo (only on the sun) and focus ring (only while shown) keep it, and are created only for the nodes that show them, like shadows. Nodes coming or going in a flight are drawn flat (`drawsFlat`): they're often huge on screen as the camera sweeps past, and blurring their shadows stalls software rasterizers.
- Never change an inherited property (a cursor, a color, a custom property) on the canvas or the world while the map moves: every element under it is restyled, 5,000 on a big map. The grabbing cursor of a drag changes on the canvas and the ring bands only; the world sets its own cursor, so the change stops there. The canvas never selects text either: a drag that could would have the browser work out a selection on every move.
- No container queries on the map: a size container around it made Chromium restyle and lay out the whole map whenever nodes came or went. Narrow maps get `orbit--narrow` from their width (`NARROW_MAP`); the root keeps `contain: size layout style`.
- A resize within `RELAYOUT_THRESHOLD` of the size the view was laid out for keeps the layout (a page's toolbar changing height by a pixel); a bigger one during a flight is laid out once it lands.

Crowded orbits: planets without moons that need several rings pack closer (`ringPlan` in `layout.ts`, the smaller of the roomy and close plans), and views of more than `CROWDED_ORBIT` planets draw them flat, as `drawsFlat` does for bodies under 12 px: no blurred shadow, which is the costliest thing to paint. The export follows the same rule.

`bun run bench` (`scripts/bench-animations.mjs`) measures frame rates and Orbit's time per frame on `scripts/large-map.js`, a made-up 2,400-idea map (the website's home page shows a copy) whose widest table puts 260 columns in one orbit, and reports each animation against the goal of 60 fps. `-- --map=huge` measures `hugeOrbits()` instead: an orbit of 150 planets with 900 moons and one of 1,000 planets, which spins must hold 60 fps on too (`-- --strict` fails when one doesn't). `-- --profile=phone` uses a phone-sized screen with the CPU slowed 4×; `-- --trace --out=<folder>` saves a Chrome trace of each animation. Run it before and after changing the paint path.

### Themes

Presets in `core/themes.ts` are complete token maps; `themeStylesheet()` turns them into `.orbit[data-orbit-theme]` rules, and a token may refer to another (`label-font` defaults to `var(--_orbit-font-family)`). Each node group, ring and link carries its own color inline (`--orbit-node-color`, `--orbit-ring-color`, `--orbit-link-color`), and `orbit.scss` mixes it with theme tokens (`color-mix(in oklab, <own> <tint>, <token>)`) for rims, shadows, the sun's halo, orbits and lines. Those mixes must live in the stylesheet: a token can't refer to a per-node property, because custom properties resolve where they're declared (on `.orbit`). The shading gradient's stops are styled from tokens too (`SHADE_STOPS` in `views.ts`). `engine/export.ts` mirrors every one of these rules for SVG export, so change both together. Labels pick the theme's light or dark text by WCAG contrast (`prefersLightText`). `tests/themes.test.ts` checks every preset's label contrast (≥ 4.5:1) for every color, shade and role, including the shading and translucent fills over the backdrop; run it after touching a palette or shading token.

### Sizing (React wrapper)

`OrbitMindMap` takes no `width` / `height` props. It renders a single `<div>` with inline `width: 100%; height: 100%; overflow: hidden` and the consumer's `className`. Don't reintroduce pixel sizing in the library — the renderer measures its root element, so the consumer's wrapper controls dimensions. The consumer is responsible for providing a sized wrapper element.

## Build script (`scripts/build.ts`)

The package is ESM-only. The build **must run with `splitting: true`**. It also writes `dist/web-page.js` (`scripts/build-web-page.ts`): Orbit and a web page's own script (`core/web-page/runtime.ts`, started by `start.ts`) in one classic script, which `exportWebPage()` (`core/web-page/page.ts`) puts inside the pages it makes as a JSON string, run from a script element it creates, so nothing in Orbit's code can end an HTML element early. Tests that export pages build it when there's no build yet. Without it, multi-entry ESM emits bare `export { ... }` shims with no source for entries whose exports get inlined into another entry — producing runtime `Export 'X' is not defined in module` errors. Splitting makes Bun emit shared `chunk-*.js` files and turn each entry into a stub that imports + re-exports from them. `scripts/sass-plugin.ts` compiles `.scss` imports for both the build and the test preload.

## Testing

`bun:test` with happy-dom registered via `tests/setup.ts` (preloaded through `bunfig.toml`). happy-dom does no layout and its `ResizeObserver` doesn't fire, so renderer tests use `tests/helpers/renderer.ts`:

- `useMapSize(width, height)` stubs `readContainerSize` for the file; `mount(source, options)` renders with flights off (`transitionDuration: 0`), so navigation lands at once.
- `manualClock()` takes over `requestAnimationFrame` and `performance.now` for tests about motion (flights, spin, glide); `useReducedMotion()` makes maps draw without animating in.
- `pointer()` and `wheel()` build synthetic events with the fields the gesture code reads (happy-dom's `WheelEvent` has no `clientX` or `ctrlKey`); `internals(renderer)` exposes the camera, scene and spin state.

The React wrapper test uses `renderToString` for markup and a DOM root for effects.

The media viewer's tests give it a fixed stage by replacing `MediaViewer.prototype.readStageBox`, and load a picture by defining its `naturalWidth` and `naturalHeight` and dispatching `load`. Provider players are tested with a stand-in `contentWindow` on the frame and `message` events from it; in the browser tests, `page.route` serves a stand-in YouTube player, so no test reaches YouTube or Vimeo.

Browser tests (`e2e/`, Playwright, desktop and phone profiles) run against `e2e/pages/fixture.html` (and `embedded.html`, a map in a page that scrolls), served with the build by `e2e/serve.mjs`. Run them with `bun run test:browser`, which uses the `mcr.microsoft.com/playwright` image so screenshots in `e2e/screenshots/` match CI; refresh them with `bun run test:browser -- --update-snapshots` after an intended visual change. The screenshots and the test pages' pictures and video are in Git LFS (`.gitattributes`): a checkout without it has their pointers, and the browser tests fail. Only CI's browser job fetches them: the unit tests never read those files, and they run with `CI` set, where Bun refuses `.only` (even reading `it.only`). `CI=true bun test` in a clone made with `GIT_LFS_SKIP_SMUDGE=1` runs them as CI does. `docs/media` stays in Git, because npm's page and the skill's references load those pictures from GitHub's raw files, which serve LFS pointers. Momentum tests dispatch pointer events with exact timestamps (`drag()` in `e2e/helpers.ts`): driving the mouse through the runner adds tens of milliseconds per step, which the spin physics rightly reads as a pause before release.

## Conventions

- TypeScript strict, ESM-first; no runtime dependencies in the core (`src/core`).
- Code style, which `bun run lint` checks and `bunx eslint --fix .` applies. The rules ESLint has no settings for are in `scripts/eslint-style.js`, with their examples in `tests/eslint-style.test.ts`.
  - **Functions are arrow functions:** `export const interpolate = (from: number, to: number, progress: number): number => { … };`. Only a function that can't be one stays a `function`: a generator, an overloaded function, an assertion function (`asserts value is …`), or one that uses its own `this` or `arguments`. Class methods stay methods. A constant can't be used before its line has run, so a function that code at the top level calls goes above that code.
  - **A block has a blank line before and after it,** unless it starts or ends the block it's in. Blocks are `if`s, loops, `switch`es and `try`s, and statements on several lines whose last line closes a block: functions, classes, interfaces, and calls with a callback. An object or a call on several lines is not a block.
  - **A member with a doc comment has a blank line before its comment and after it,** unless it's the first or the last. This applies in interfaces, object types, classes, objects and enums.
  - Every `if`, `else` and loop has braces.
- React and `marked` integrations stay on their own subpaths so the core remains usable without those peers.
- Update the README and `docs/` when user-facing behavior changes. There is no changelog: what a release changes is written up when it's published (see `RELEASE.md`).
- `docs/format.md` is the format reference people and coding agents write maps from; `tests/docs.test.ts` checks its examples and tables against the parser. After editing the README, `llms.txt` or `docs/`, run `bun run docs:llms` to rebuild `llms-full.txt` and the skill's references (`skills/orbit/references/`); the same test fails while they are stale.
- `skills/orbit/` is the skill the package ships for agents that use Orbit, in the [Agent Skills](https://agentskills.io) format that Codex, Claude Code, Kimi Code and others read: keep its frontmatter to `name` and `description`, and `SKILL.md` short, with the detail in `references/` (copies of `docs/` that `bun run docs:llms` makes, pointing links to other files at the repository). `tests/docs.test.ts` checks its format, its links and its list of themes. After changing it, install it in a scratch project with `npx skills add <this checkout> -a codex -a claude-code -a kimi-code-cli --copy` and ask each agent to use it.
- Release from the repository root; see `RELEASE.md` for the checklist.
